Model backends

An AI agent does not know which model it talks to. Its record names a backend, a bundle that turns the conversation into one request to a provider and streams text back. Fantastic ships five: anthropic_backend, vllm_backend, ollama_backend, responses_backend and foundation_models_backend.

This page covers what the five share, what each one adds, the three caching modes and the transport_retries setting. Folds, the history and marks are on Context folding and Forking and marks.

Updated 2026-10-27 · 6 min read · 3 animations

One surface, five providers

The shared code is ai_core, the crate the AI agent page follows. It owns the verbs (send and the rest), the per-client history, the FIFO lock that serializes callers, prompt assembly and the status events. A backend supplies only a provider: messages in, content tokens out.

A provider is a PURE RAW-TEXT streamer: it takes plain chat messages (role system/user/assistant/…, text content) and yields content tokens

provider.rs

No backend uses a provider’s native tool API. The model writes its <call name=…> envelope as plain text, the provider streams that text through without reading it, and ai_core parses and routes it. Adding a provider therefore teaches it nothing about tools. A provider holds no agent state; its one protocol duty is to wrap the model’s reasoning channel in <think>…</think> once per turn, so a reasoning model’s turn does not read as empty.

Every backend answers the same verbs because each one’s verb list starts from ai_core’s (Anthropic and vLLM add usage; Anthropic also adds usage_reset and models). send runs one turn on text and returns {response, final, client_id}. The call gate, refusals and ledger work as on any other agent; see The call gate.

Rust ships all five backends. Python ships four: it has no Foundation Models backend, because that one is Apple-only native code.

What each backend adds

backendrequestrecord fields it requireskey
anthropic_backendPOST to the Messages URL, SSEendpoint, modeloptional credentials, sent as x-api-key
vllm_backendPOST {endpoint}/chat/completionsendpoint, kv_overflowoptional credentials, sent as Bearer
ollama_backendPOST {endpoint}/api/chat, line-delimited JSONendpointoptional credentials, sent as Bearer
responses_backendPOST to the full …/v1/responses URL, SSEendpoint, model, credentialsrequired, sent as Bearer
foundation_models_backendone on-device requestnonenone: a credentials field is refused

Where a field can be read from the server, the backend reads it before a turn and writes it into the record: max_tokens and context_window from the API for Anthropic, the served model, max_tokens, context_window and kv_slots for vLLM, and the model from GET /api/tags for Ollama. A key is read from a credential store at each request and sent only to the ref’s host; the record holds the name, never the secret (Security).

Anthropic

One top-level system string joins every system message, and consecutive turns of one role are merged. max_tokens goes on every request because the API requires it. With thinking_budget set (at least 1024, below max_tokens) the thinking streams first, wrapped in <think>. A stream that ends without message_stop did not finish, and an error event is raised with the API’s own type and message. The agent also counts tokens, side calls included, in its own usage.json; the usage and usage_reset verbs read and zero them, and models lists what the key can use.

vLLM

The backend talks to the server directly, with no proxy. It reads both delta.reasoning_content and delta.content, since reading content alone drops whole turns of a reasoning model. It sends one system message, at index 0. A stream that ends with no finish_reason is an error, never a completion. server_dialect (vllm, strata or llamacpp) says how the server names its thinking budget and is set, never guessed.

vLLM also gets a session table per endpoint. kv_slots is how many conversations may be live there, and kv_overflow decides what happens when all are: evict rotates the least-recently-used conversation out, reject refuses the newcomer with KvSlotsFull. A slot frees itself after kv_ttl idle seconds (default 1800). The code calls this bookkeeping: it frees no GPU memory and sees only this kernel’s traffic. A side call, such as a fold summary, takes no slot.

Ollama

The backend reads both the thinking and the content field of each line and wraps the thinking in <think>. Optional fields include num_ctx, num_predict, think and stream_idle_seconds. A non-2xx answer fails the turn as <error> (status code: n).

OpenAI Responses

The backend is stateless: store:false, and the whole conversation goes with every pass, as instructions plus typed message items. It guesses no host and no model, and credentials is required. A function_call item in the output is a loud error, because tools are never native. max_tokens is sent as max_output_tokens and defaults to 8192.

Apple Foundation Models

The on-device system model runs through a Swift core linked into the Rust crate. A record that names endpoint, model or credentials is refused at the write, since none of them means anything here. The context window is the model’s own, and a record may name only a smaller one. If the model is unavailable, the turn fails loud, naming why (device not eligible, Apple Intelligence not enabled, model not ready, or not macOS 26+). It is checked first in the turn, and nothing falls back to another backend. The backend is registered on every platform, and the failure appears when an agent uses it.

Caching modes

The caching field decides how the model’s view of the history is built. cleanup is the default.

modethe view
noneevery stored row, in order, never trimmed
cleanupsuperseded whole-state reads, repeated reply bodies and used docs drop out; no markers
provider_cachenone’s history plus two markers: the end of the primer row (cache_primer_until) and the end of the last fold or clear row

ai_core only flags the two messages. The backend turns the flags into its own markers, and only in provider_cache. Anthropic is the only backend that declares it. It sends ephemeral cache_control markers on the system block, on the block that ends the primer row, on the block that ends the last fold, and one top-level automatic marker: at most four. In every other mode the body carries none.

A backend that cannot cache refuses the mode, at the write and again at the turn.

The primer row and every row before it are pinned in any mode: context_fold will not fold a range that starts at or before it. Why old bytes never move, and how folds use this, is on Context folding.

Transport retries

Each provider error carries a transport flag. It is true when the failure is the link, not the model or the request: a connect failure, a stream that stalls or drops, or a transient gateway error. A stalled stream is detected by the idle clock, stream_idle_seconds (default 60), which covers the response headers and every read of the body.

The record field transport_retries is an int from 0 to 5, and 0 is the default, which means off. When a pass fails with a transport error and retries remain, ai_core stores a notice row, emits a status event with phase retrying, waits, and runs the pass again.

The wait doubles: 2 s, 4 s, 8 s and so on. The notice row is stored in the history, so the model reads it on the next pass and the operator sees it. A cancel that lands during the wait ends the turn. A failure that is not a transport failure, or a transport failure after the last retry, ends the turn with the error as usual. Rust and Python do the same.

What each backend calls a transport failure

backendretried by transport_retries
anthropic_backendconnect failure or timeout, a dropped stream, HTTP 502, 503, 504 and 529
vllm_backenda stall, a dropped stream, HTTP 502, 503 and 504
ollama_backenda failed request, a stall or a broken stream; an HTTP error status is not retried
responses_backenda failed request, and HTTP 502, 503 or 504 once its own retries are spent
foundation_models_backendnone: the code marks no failure as a link failure

The Responses backend has a retry of its own, below this one. A 502, 503, 504 or 520 to 524 whose body is not JSON, which is a CDN or proxy error page, is retried twice inside the request, waiting 1.5 s times the attempt number. A 4xx, or a 5xx with a JSON body, stays loud.

The field’s hint lists 502, 503 and 504. The Anthropic code also treats 529 (overloaded) as transport, so this page follows the code.

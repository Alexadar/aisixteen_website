Foundations

Agents

Everything in Fantastic is an agent, so what it can do is the set of agents it ships. Each is a bundle that answers its own verbs behind the same call gate.

Updated 2026-10-27 · 1 min read · 1 animation

What ships

  • AI agents over vLLM, Ollama, the OpenAI Responses API and Anthropic’s Messages API, plus Apple’s on-device model on macOS. Tool calling is Fantastic’s own prompt-taught <call> grammar, not a provider tool API, so any capable model drives the same verbs. AI agent follows one turn, and Model backends the five providers.
  • Memory: every message lives in a memory store agent. AI agents fold, recall and page their own history.
  • IO legs: the file agent (file_bridge) for files, edits, streams and watches; the exec bridge for allowlisted commands, terminals and a control wire back to the kernel; the web host with its web_ws and web_rest legs for the browser and HTTP; the bridge (ws_bridge) from one kernel to another; and the MCP client for a remote MCP server’s tools as verbs.
  • Programs: a program agent is a process that answers its folder bundle’s verbs over the exec bridge’s control wire.
  • Kernel services: the scheduler for recurring sends, the static loader for a roster declared in fantastic.yaml, and credentials by reference, with keys bound to one host.
  • Teams: agentic resources and tasks spawn agents from role cards under limits and record who holds each task. Both are off by default.

The AI agent keeps a long conversation in a finite window by folding it: a finished stretch of work becomes one appended row that names what it hides.

In this part

  • AI agentOne pass behind a provider seam, tools written as text calls, a chain that ends with done, history as rows, pause and resume.
  • Memory storesOne surface, two stores: rows keyed by caller, fold refs that cascade, a SQLite file or RAM, and a record field that picks which.
  • Credential storeDeclare a ref and its host, set the value, read it per request; file, keychain or env.
  • Exec bridgeRuns allowlisted commands as jobs, serves terminals, and gives each child a wire to the kernel.
  • File agentThe file bridge is an agent over a folder. Callers read, edit, stream, list, rename, delete and watch files by sending it verbs.
  • MCP clientOne remote MCP server as an agent: boot lists its tools, and each tool is a verb.
  • Web agentsweb hosts HTTP and mounts the routes its web_ws and web_rest children declare.
  • BridgeA ws_bridge agent dials another kernel and ships raw call frames: the wire, the frame ids, the 30 s wait and a dropped link.
  • SchedulerA schedule repeats one send every N seconds; the loop sleeps until the next fire, and each fire goes out as the scheduler.
  • Program agentsA program says hello with its verbs, answers calls, can send and emit, and stops with a reason.
  • Static loaderA `fantastic.yaml` lists the agents; the loader creates them at the kernel’s own boot and re-applies the file on every restart.
  • Agentic resources and tasks`agentic_resources` spawns agents from role cards and counts every one that still exists against its limits. `task_registry` records who holds each task and where it came from. Both are off until the host turns them on.
